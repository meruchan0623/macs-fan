# 逐来源采样与磁盘缓存

SMC、HID、Intel registry GPU继续使用每次隔离worker请求的新样本；整份快照的capturedAtMs始终是开始时间。磁盘SMART来源由`src-tauri/src/disk_cache.rs`在同一worker内按单调时钟每30秒最多调用一次，启动或worker重建立即读取；该间隔不是跨进程或重启后的全局限流。

磁盘底层在进入IOKit之前记录wall-clock时间。缓存复制保留该captured_at_ms，成功和失败批次都替换旧批次并使用相同轮询间隔。失败没有历史温度回填，也没有紧循环重试。当前批次最多16个来源，缓存没有无界历史队列。每轮重新枚举，因此插拔通常在下一次磁盘读取时反映；缓存期间不声称确认设备仍连接。

`monitor.rs::merge_disk`输出每源sampledAtMs和expiresAtMs（开始时刻+45秒）；计算溢出、采样时刻在未来或期限已到时输出quality=stale、temperatureC=null。ProviderStatus.cached区分缓存和刚完成的批次，provider capturedAtMs仍为源时间，不能拿全局快照时间替代。磁盘来源不与SMC/HID NAND猜测配对，资料标签和解码均不构成控制准入。

前端有任一逐源时间字段时必须校验两个字段，拒绝null、非安全整数、负采样时间、未来采样、非正期限或超过45秒的寿命；只有完全不含两字段的旧来源沿用全快照新鲜度。过期不参与有效温度排序或overview主来源选择，并显示“—”。实际采样时刻和过期信息只放在行hover/aria，界面不增加说明区。1秒计时器比较带时间字段来源的新鲜度状态，仅在状态变化（过期、时钟回拨或恢复）时更新传感器表，即使下一次采样正在等待，也不把旧温度继续显示成有效值。

单调时钟负责轮询节流，wall-clock字段供跨进程显示。系统时钟跳变可能暂时使来源不可用，不能通过重新给缓存打时间戳掩盖。新鲜度是显示期限，不代表温度校准或热安全保证。同步SMART/IOKit调用依赖既有6秒worker边界，不能保证取消不可中断的内核I/O；真实控制准入仍为空。

测试覆盖30秒边界、无新I/O缓存、失败替换、单调时间逆转/长暂停、输出副本隔离、45秒截止/未来/溢出、部分字段格式、旧来源兼容、重复名称、SMC独立保留、全量wire上限及真实app.js的受控时钟/DOM期限跨越。故障注入不等于ATA实机或真实睡眠/唤醒验收。
