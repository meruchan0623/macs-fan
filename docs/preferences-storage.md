# Local preferences and presets (0.6)

The application stores its own configuration in `app.path().app_config_dir()/preferences.json`. The Tauri host derives the directory from the application identifier; IPC cannot supply a path. The original application's Qt/QSettings domain is never read or written. Static vendor findings in `../../preset-analysis.md` are context only, not a storage source or compatibility promise.

`preferences_read()` returns the schema-1 document from [preferences-contract.md](preferences-contract.md). A missing directory or file returns defaults with revision 0 without creating anything. `preferences_update({expectedRevision, update})` accepts only the four tagged operations in that contract and returns the committed document. Commands run filesystem work on Tauri's blocking executor. Preset selection is editor selection; no command applies settings, connects a controller, or touches hardware.

Saving trims names, generates a stable 128-bit CSPRNG identifier for a new preset, checks portable constraints, and selects the saved preset for editing. Updates require existing IDs for editing/deleting and reject dangling selections. Case-insensitive name comparison uses Unicode lowercase. All documents, nested records, mode variants and update variants reject unknown fields. Required nullable IDs must be explicitly present. Unknown schema versions, malformed JSON, invalid records and files over 1 MiB are rejected and preserved. Reads are bounded even if file size changes during reading.

Every writer opens the dedicated application directory, opens a persistent `.preferences.lock`, obtains an exclusive Unix `flock`, then rereads and validates the document before comparing `expectedRevision`. Concurrent writers with the same expected revision cannot overwrite one another: one commits and the other receives an error containing `配置已被其他窗口或进程修改`. Revision increases only for a changed, valid document; selecting the current selection or saving identical contents returns the current revision. Revisions cannot exceed JavaScript's maximum safe integer. The frontend should retain its draft, reread, and ask the user to reconcile a conflict.

Filesystem operations walk absolute directory components with `openat(O_DIRECTORY | O_NOFOLLOW)` and retain the resulting descriptor. Symlinks in the application directory or its ancestors are rejected. Missing directories are created only on writes, with mode 0700; existing permissions are never changed. The final application directory must belong to the current user and must not be writable by other users. Targets and locks use `O_NOFOLLOW`, must be regular, current-user-owned, single-link files, and are opened nonblocking so a FIFO cannot hang the command. The lock uses create mode 0600. Descriptor-relative operations prevent a renamed directory from redirecting subsequent reads or writes. This does not claim protection from arbitrary code already executing as the same user.

A changed document is serialized and bounded before creating a uniquely named temporary file with `O_CREAT | O_EXCL`, mode 0600. The writer writes all bytes, syncs the temporary file, checks the target again, atomically renames within the same directory, then syncs the directory. Newly created directory entries are also synced. Before-rename failures leave the original document intact and remove this writer's temporary file. Symlinks and damaged/future files are never replaced as a recovery shortcut. The application neither modifies system trust nor changes another application's preferences.

A directory-sync failure after rename is inherently ambiguous: the new file is already visible, but crash durability has not been confirmed. The command rejects with `配置可能已提交，但目录同步失败；请重新读取确认后再操作` rather than claiming successful durability or rolling back a potentially committed update. The caller must keep its draft and reread. If the file contains the new revision, retrying with the old revision correctly conflicts. A read establishes current contents, not a guarantee that a preceding failed sync became durable.

Focused Rust tests use only isolated temporary directories. They cover missing-read behavior, CRUD and restart persistence, stable IDs, no-op revision behavior, permissions, strict IPC/file schemas, validation bounds, corruption/future/oversized preservation, dangling IDs, stale conflicts, real subprocess writer contention, rejected directory/file/lock symlinks and nonregular files, a precommit filesystem failure, and injected post-rename sync failure with reread recovery. No test reads real user preferences or calls hardware.

The four view choices (`scope`, `sort`, `unit`, `precision`) deserialize strictly from strings. Serde's alternative unit-enum representation such as `{"overview":null}` is rejected in stored documents and update payloads, just like bare null. Invalid files remain untouched.

Native exit handling also preserves the editor draft. The frontend installs its `editor-exit-requested` listener first, invokes synchronous `editor_state({dirty:false})`, and enables editing only after that initial handshake returns. The host then keeps a monotonic ready flag for the process lifetime; later dirty arguments remain wire-compatible but do not control native exit decisions. Every normal `ExitRequested` after readiness is prevented, the main window is shown, and only that window receives `editor-exit-requested`. The frontend automatically approves a clean exit or shows its custom discard confirmation for an unsaved draft. This protects a new edit even while its dirty-state IPC is still pending, and leaves the process alive while JavaScript handles the request. Tray quit and the normal application quit route use this same event.

After the frontend approves an exit, it invokes `exit_after_discard()`, which grants a one-shot native approval and calls `app.exit(0)`. Only the next `ExitRequested` consumes that approval; readiness is never reset. Closing the window with a working tray continues to hide it and retains the draft. When the tray or hiding is unavailable, a ready editor prevents a real close and receives the same confirmation event; this window-close fallback never consumes exit approval. No new permissions are required. A webview that hangs after the ready handshake may require Force Quit because the host keeps blocking unapproved normal exits. Force quit, process crashes and OS termination cannot be guaranteed against, and drafts are not crash-persisted.

The first native Cmd+Q smoke test exposed a separate bypass: Tauri 2.12.5's default macOS application menu uses a predefined Quit item, and muda 0.20.0 dispatches that item directly to AppKit's `terminate:` selector. Checking only `AppHandle::exit` source and passing Rust guard tests was insufficient to establish native keyboard behavior. The application now creates Tauri's default menu, replaces only its first macOS application submenu with About/Services/Hide/Hide Others/Show All and a custom `quit-main` item, and preserves the other default menus. The custom Cmd+Q accelerator and application Quit click call `app.exit(0)` through an ID-specific global menu handler, entering the same guard as tray quit. No localized-title matching is used. This protected application-menu installation is mandatory in setup: failure aborts startup before the editor readiness handshake, while tray installation retains its existing fallback. Native Cmd+Q must be retested on the rebuilt application; compilation and guard state tests alone do not establish that result.
