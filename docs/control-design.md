# 温控策略与生产写入边界

0.16源码已接GUI显式应用/停止、持久认证客户端、单账本Coordinator、受profile约束的控制构造及严格能力握手。宿主真实温度候选读取已接入，但始终Unverified，不可用于温控。实际生产入口继续选择永久只读构造，profile表为空；发行身份、真实校准与逐机型写入/独立恢复证据仍缺。仅提供证书仍不会使本机可调速。当前契约见[control-bridge.md](control-bridge.md)与[production-control.md](../helper/docs/production-control.md)。

`control-runtime/src/policy.rs` 本身是无外部依赖的纯策略模块，输出 `SuggestRpm` 建议和 `ReturnToAutomatic` 恢复建议；Coordinator负责将其交给执行器。纯策略输出不代表硬件已执行或成功。界面只能在真实写入及读回确认后表达硬件“已应用”“已恢复自动”；Fake状态仅证明软件链。

本设计参考 `../../reverse-engineering-report.md` 的已核实静态事实，不复用原厂 helper、签名身份、二进制或授权机制，也不声称复现了原厂完整算法。

## 可执行的研究规范

配置在创建策略时验证，并在实例内保持不可变。RPM 上下限必须有限、非负且有序；两者允许相等以研究恒定曲线。温度起调点与最高点必须有限，满足 `0 ≤ low < high ≤ 120°C`。样本超时为 1–60000 ms，降速率有限且大于零，恢复样本数至少为一。零降速等待表示立即进入限速阶段。RPM 合法性这里只证明数学范围，不能替代真实机型及风扇能力校验。

曲线使用浮点线性插值，低于起点夹紧到最小 RPM，高于终点夹紧到最大 RPM，中间保留小数，不做整数温度或斜率截断。预览函数只计算曲线，不证明样本可信或策略已恢复。

每次 `evaluate` 接收当前单调时间和可选样本。样本包含摄氏温度、采样单调时间、质量；采样器和策略必须共享时钟起点。拒绝缺失、非 Verified 质量、NaN/无穷、超出研究接受域 `[-20,127]°C`、未来、过期及时间戳重复或倒退的样本。超时边界等于 timeout 可接受，大于 timeout 拒绝。此宽泛温度域不等于每个传感器均可用于控制，适配器必须提供额外的机型和传感器可信性证明。禁止通过重写时间戳把缓存值变成新样本；禁止随机修补读数。

策略启动时处于熔断状态。任一故障立即清除旧建议和降速状态，并输出 `ReturnToAutomatic(原因)`；连续达到配置数量的全新有效样本后才恢复输出建议，期间返回 Recovering。失败会把恢复计数归零，重复样本不能推进恢复。恢复后的首个 RPM 从当前曲线重新计算，不能继承故障前目标。单调时间倒退立即熔断并清除采样时序，下一轮按新时钟起点重新恢复；未来执行器必须同时撤销旧租约，不能把时钟重置当作续租。

更高的曲线目标立即生效为建议，不受降速限制。较低目标必须先连续等待 descent_hold_ms，然后按 descent_rpm_per_second 限制下降；等待期之前的时间不累计为可下降量。目标回升到上次建议或更高时取消降速等待。等待截止时间溢出时保持原建议，绝不通过整数回绕提前降速。每个结果仍夹紧在配置范围。等待是时间迟滞，尚未设计额外温度死区。

调用者必须在每个轮询 tick 调用，包括读取失败时传入 None；本模块本身没有定时器。若调用者停止运行，本模块不能主动恢复任何硬件，宿主看门狗与执行层负责撤销及恢复。现有timer不能抢占阻塞IOKit，helper自身崩溃后的独立硬件恢复仍无证明。休眠行为需要执行层事件处理，不能假设所选单调时钟一定计入睡眠时间。

可独立验证：

```sh
rustc --edition=2021 --test control-runtime/src/policy.rs -o /tmp/macs-fan-policy-tests
/tmp/macs-fan-policy-tests
```

测试覆盖配置拒绝、连续小数插值、端点夹紧、固定范围、非有限/越界/质量/时效错误、立即升速、等待后的限速降速、熔断后连续恢复、重放、时间回退及截止时间溢出。这些测试验证策略状态机，不能作为硬件写入、热安全或跨机型验收。

## 未来特权 helper 的必要条件

当前软件已按无特权 UI、纯策略和独立最小helper划分，以下要求约束未来生产写入。所有写入仅能从helper发起；UI永不持有任意IOKit/SMC写入接口。当前缺少有效发行身份、公证条件及真实硬件准入，因此不注册或启动root helper，也不降级为复用原厂服务、常驻root脚本或无认证IPC。身份/服务外部条件与已落盘的控制构造、能力握手、未准入候选采样分别追踪，见 [原始目标账本](../../requirements-matrix.md)。

1. **身份认证。** 使用独立 bundle ID、固定 Team ID 与 designated requirement，通过 ServiceManagement 支持的安装机制部署。每条 XPC 连接通过系统逐消息代码签名要求校验真实客户端签名、身份及允许的 requirement，不信任消息传入的 PID、路径、Team ID 或自报身份。拒绝未授权客户端和替换二进制。反向验证服务身份，避免 UI 连接伪造 helper。签名校验失败关闭写入能力。
2. **固定能力。** 协议仅暴露枚举操作：获取已验证风扇能力、请求自动、请求限时 RPM。禁止传入任意 SMC key、原始字节、选择器或 shell 命令。允许写入键由经过审核的机型适配表固定，绑定风扇编号、编码、尺寸、控制模式和可支持数量。未知机型、未知键、风扇计数失败及编码不明均拒绝控制。
3. **双重范围校验。** helper 自行读取并核实机型及风扇 min/max，不信任 UI 上报范围。再次拒绝非有限、负值、超范围 RPM、错误风扇号及已变化的硬件状态；按设备编码规则处理量化，禁止静默越界。策略配置必须同时落在 helper 的能力范围内。零 RPM 仅在机型明确允许时开放。
4. **用户同意。** 安装权限与启用温控分别说明并取得用户主动同意。默认固件自动；用户可随时停止并撤销控制。每个会话绑定授权用户、客户端身份及具体风扇，不把旧配置自动当作新会话同意，不在后台启动时自行夺取控制。
5. **租约与看门狗。** 有效手动控制必须持有短期、不可重放的租约和递增序列号；helper 用自己的单调时钟验证到期，限制最大租期并独立定时监测。断线、客户端崩溃/退出、心跳丢失、租约过期、时钟异常、helper 更新以及任何采样或执行故障均触发恢复自动。写入串行化，同一风扇仅有一个所有者；不与其他温控程序竞争，不通过不断重写抢占控制。
6. **生命周期。** 睡眠前先撤销租约并恢复自动；唤醒后重新检测能力、重建采样质量及用户控制会话，禁止使用睡眠前目标。正常退出与停止操作等待恢复读回。强制退出由 helper 的看门狗补救。helper 自身崩溃可能使手动模式残留，必须有经过硬件验证的独立恢复机制或固件自动超时；若无法证明该场景可恢复，则不得开放写入功能。系统电源事件、XPC invalidation/interruption 与退出事件均有测试。
7. **写入与读回。** 对模式和目标写入分别检查返回码，随后读回模式与目标；实际 RPM 的惯性应另以合理时间窗观察，不把瞬时实际 RPM 差异误认为写入成功或失败。未确认、超时或部分成功统一进入故障恢复；恢复自动也必须检查返回码和模式读回。恢复失败明确报告“未确认恢复”，保留故障状态并采取有界重试和显式告警，不能报告假成功或无期限重试。审计记录时间、设备、操作、租约和结果，不记录凭据。

## 开放控制前的验收门槛

需要独立签名及公证链路、真实 XPC 身份伪造/替换测试、未知机型及恶意请求拒绝测试，以及多机型真实硬件的读写往返验证。对断连、进程强杀、helper 强杀、睡眠/唤醒、时钟异常、传感器冻结、返回码错误、读回不一致和固件恢复失败注入故障。逐项证明硬件回到自动控制，记录有限恢复时间和无法覆盖的故障边界。上述要求是未来方案，不是本版本已实现的能力；当前发行版控制入口必须保持不可用。

## 历史接入阶段

以下记录各版本当时的进展；其中“GUI未链接”“尚未构造Coordinator”等表述仅适用于该历史阶段。当前状态以本文开头及 [control-bridge.md](control-bridge.md) 为准。

### 0.3

`../control-core`已实现独立事务/租约核心；`../helper`已实现macOS13+非特权NSXPC验证工程，使用系统逐消息代码要求，严格协议连接核心的Fake/Unavailable执行器。真实跨进程、身份错误拒绝、配置篡改拒绝、独立timer及断线撤销已验证，见其docs/architecture.md与verification.json。主GUI未链接这条通道，仍为只读。后续已接入不可升权的真实SMC只读adapter（helper/docs/readonly-integration.md）；仍没有可写硬件后端、生产发行身份或ServiceManagement安装；上文硬件和权限门槛仍然适用。

### 0.7

已实现固定身份的只读LaunchDaemon宿主、SMAppService固定服务桥接、Tauri无参数服务命令和应用内helper/plist封装。诊断仅按需查询状态；没有自动注册或批准。主GUI仍直接使用独立只读采样worker，未建立生产XPC控制连接。固定Team为空，实际生产身份校验与注册被拒绝；发行版hardware_write_enabled仍为false。

两路独立审查与负向、stub测试通过，真实打包/严格ad-hoc签名已验证。它们不替代正式签名、真实管理员批准、root/跨用户认证连接、安装更新生命周期、机型写入读回和独立故障恢复。只有这些门槛均有证据后才可开放控制。

### 0.8 认证观察接线

GUI诊断已接入固定生产NSXPC只读检查客户端和双向身份前置条件，当前因Team未配置返回blocked；不等于已建立实际生产认证会话。macOS13+固定privileged Mach服务连接、发送前设置要求、单调回复截止、异常清理与并发限制均已实现；测试用非特权XPC服务证明协议互通，不能替代真实root/Team验收。GUI控制操作、策略执行、可写profile和独立恢复仍未开放。

### 0.9 持续执行与目标事务

纯建议之上新增独立control-runtime。协调器只从Actuator/TokenSource/Clock创建全新Engine，不能吞入已有活动/恢复租约；显式start预检整份计划，连续采样后才允许首笔写操作。传感器建议经可信能力量化，同目标续租、变目标SetTarget；失败停止全会话，恢复结果与应用状态分开。

独立watchdog同时检查租约与已保存传感器样本的截止，不能仅等较长租约过期。停止、断线、睡眠、关闭和时钟回退不会自行恢复旧会话。临时Fake与真实非特权通信验收证明软件状态转换，当前SMC只读验证仍拒绝控制。

实际GUI/生产host尚未构造Coordinator；闭合生产写入连接、可信传感器接入、独立I/O恢复和真实机型准入仍未完成。完整API/时间/宿主责任见../control-runtime/README.md，目标更新事务见../control-core/docs/new-target-update.md。

### 0.10 实际宿主接线

HostState已使用唯一Coordinator账本处理直接租约和固定计划；NSXPC认证连接的owner绑定计划token与最长5秒授权。原100ms宿主timer独立续1秒核心租约并检查授权到期；预检/查询慢调用后重新审计，target/manual每次底层写前执行授权期限检查，恢复Automatic允许执行。成功仅在实际读回后表达，过期成功token不发送。

温控policy库仍已实现，但宿主没有校准过的本地temperature provider，sensor计划明确sensor_source_unavailable。GUI尚未提供应用计划命令。写前期限检查不能抢占已经进入的IOKit调用；生产根服务、正式签名、可信温度、硬件允许表和进程死亡独立恢复仍未完成。
